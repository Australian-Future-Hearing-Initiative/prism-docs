Firebase Setup

PRISM stores its researcher accounts, experiments and participant data in a Firebase project that you own. This guide walks you through creating that project in the Firebase Console and collecting the details the PRISM installer asks for. Complete it before following the Setup Guide.

By the end of this guide you will have:

  • A Firebase project on the pay-as-you-go Blaze plan.
  • A registered Android app and its google-services.json file.
  • A registered web app and its Web API Key (apiKey).

You will need a Google account, plus a payment method or access to an existing Cloud Billing account.

Data storage and privacy

PRISM collects audio and health data from participants. Most of it is stored in the Firebase project owned by the researcher that you create in this guide, which is hosted by Google. See Privacy and Security in Firebase and the Firebase Data Processing and Security Terms for details.

What the app uploads

While a recording session is open, the participant’s phone records audio continuously. Each time the participant presses a rating button, the app uploads:

  • An unprocessed audio clip of up to 30 seconds, ending at the button press.
  • Heart-rate variability and skin temperature readings from the previous 30 minutes, if the participant has allowed access to Android Health Connect.
  • If a watch is used, an audio clip from the watch, plus its accelerometer, gyroscope, heart-rate and ambient-temperature readings.

PRISM doesn’t collect location data, and its apps and Research Portal don’t use analytics or crash reporting.

Warning

The Upload Raw Audio and other sensor settings in the Research Portal don’t currently change what the app collects; everything listed above is uploaded with every rating.

Where data is stored

Where What’s stored
Firebase Authentication Researchers’ email addresses and password hashes. Participants’ Google account email, name and profile photo URL, from signing in to the app with Google.
Cloud Firestore (database) Experiment settings. Participants’ names, email addresses and invitation status. A record of each uploaded file: rating, sound classification, time, size and the phone’s Android device ID.
Cloud Storage (files) The uploaded files. File names include the date and time, rating, participant’s user ID, experiment ID and Android device ID, but not the participant’s name or email address.
Cloud Logging Server logs containing participants’ user IDs and device IDs, kept for 30 days by default.
Participant’s phone Audio recorded since the last rating, which stays on the phone after the session ends, and any files that failed to upload. Uploaded files are deleted. Sound classification runs on the phone.
Participant’s watch Audio clips, which the watch app doesn’t currently delete. The watch uploads nothing directly; its data goes via the phone.
Your computer / server host Any files you download. If you run PRISM locally, also its credentials, including the service account key, which gives full access to all study data.
Email provider (Mailgun or Gmail) Invited participants’ email addresses, your invitation text and the experiment link.
Google Forms (optional) Whatever your survey asks. PRISM doesn’t pass any participant details to the form.

Location, security and retention

  • Location: you choose where Firestore and Cloud Storage keep data when you set them up (for example australia-southeast1, Sydney), and you can’t change it later. Firebase Authentication doesn’t offer a choice of location. See Firebase locations.
  • Security: Firestore and Cloud Storage encrypt data in transit and at rest. Anyone with access to your Firebase project or service account key can see all study data, so keep that group small.
  • Retention and withdrawal: data stays until you delete it. Removing a participant in the Research Portal deletes their uploaded files and records, and deleting an experiment deletes all of its data. Participants’ sign-in accounts aren’t deleted automatically (delete them under Authentication in the Firebase console), and you’ll need to delete any downloaded copies yourself. Participants can’t delete their data or leave an experiment from the app, so your withdrawal procedure should ask them to contact you.

Create a Firebase project

Step 1: Name your project

Open the Firebase Console, sign in with your Google account and create a new project.

Enter a Project name (this example uses prism-nat1). Firebase creates a project ID from the name, shown underneath it. The project ID can’t be changed later and becomes part of your project’s web addresses (e.g. prism-nat1.web.app), so click the pencil icon if you’d like to edit it now. Click Continue.

Step 2: Skip Gemini in Firebase

Gemini in Firebase is an optional AI assistant for the Firebase Console. PRISM doesn’t need it, so turning it on is up to you (this example leaves it off). Click Continue.

Step 3: Turn off Google Analytics

PRISM doesn’t use Google Analytics either. Switch off Enable Google Analytics for this project (it’s on by default) and the Continue button changes to Create project. Click it, then wait for Firebase to finish creating your project.

Upgrade to the Blaze plan

New projects start on the free Spark plan. PRISM relies on paid Firebase services such as Cloud Functions, so your project must be on the pay-as-you-go Blaze plan. Blaze still includes the no-cost quota; you only pay for usage beyond it.

Step 4: Select the Blaze plan

When your project opens, click Upgrade at the bottom of the left-hand menu.

In the Firebase pricing plans dialog, click Select plan under Pay as you go (Blaze plan).

Step 5: Choose a billing account

Select an existing Cloud Billing account from the list, or click Create a Cloud Billing account and follow the prompts to add a payment method. If your organisation manages Google Cloud billing centrally, ask your administrator which account to use.

Step 6: Set a budget alert

Enter a Budget amount in USD (this example uses $5) and click Continue, or click Skip this step.

Note

A budget doesn’t cap your spending. It only emails the billing account’s administrators when the project’s costs approach or exceed the amount you set.

Step 7: Link the billing account

Review the summary and click Link Cloud Billing account.

Click Done to close the confirmation.

The badge next to your project name now reads Blaze plan.

Register the Android app

The PRISM Android app connects to your Firebase project using a google-services.json file. You only need to register the app and download this file; the PRISM installer takes care of the rest, so you don’t need Android Studio.

Step 8: Add an Android app

On the project overview, click + Add app and choose Android. Enter:

  • Android package name: a unique identifier for your build of the app, written in reverse-domain format such as com.yourorg.prism (this example uses com.nat.prism). It can’t be changed after you register the app, and the PRISM installer builds the app with this name.
  • App nickname (optional): a label that only appears in the Firebase Console, such as PRISM Android.

Click Register app.

Step 9: Download google-services.json

Click Download google-services.json and keep the file somewhere handy, since the PRISM installer will ask for it. You can ignore the Android Studio instructions. Click Next.

Step 10: Skip the SDK setup

The next screen explains how to add the Firebase SDK with Gradle. Skip these instructions: the PRISM installer configures the app for you. Click Next.

Click Continue to console.

Step 11: Find your Android app settings

Your Android app is now listed on the project overview. Click the gear icon (⚙️) on the app card whenever you need its settings, for example to download google-services.json again or to copy its App ID (only needed if you distribute the app through Firebase App Distribution).

Register the web app

The PRISM Research Portal signs researchers in through Firebase using your project’s Web API Key. You get this key by registering a web app.

Step 12: Add a web app

On the project overview, click + Add app and choose Web (</>). Enter an App nickname; we suggest prism, which is the name the Setup Guide uses. Leave Also set up Firebase Hosting unticked (it can be set up later). Click Register app.

Step 13: Copy the Web API Key

Firebase shows a firebaseConfig code snippet. Copy the value of apiKey (a long string beginning with AIza) and save it, since the PRISM installer will ask for it. You don’t need to run npm install or add this code anywhere. Click Continue to console.

Tip

You can find the key again at any time under Settings → General → Your apps → (your web app) → Config.

Next steps

Your Firebase project is ready. You should now have:

  • The google-services.json file for your Android app (Step 9).
  • Your Web API Key (Step 13).

Continue to the Setup Guide, which explains how to generate a Firebase Service Account Key and run the PRISM installer.
